# Ритм дня

Адаптивное веб-приложение на Next.js и TypeScript. Основная база данных — Turso/libSQL.

## Локальный запуск

1. Установите зависимости: `npm install`.
2. Скопируйте `.env.example` в `.env.local`.
3. Если `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` оставить пустыми, миграции создадут локальную базу `.local/nutrition-water.db`.
4. Примените миграции: `npm run db:migrate`.
5. Запустите приложение: `npm run dev`.

Вход через `http://localhost:3000/login` позволяет создать аккаунт и войти по email и паролю. В локальной разработке Better Auth использует локальный ключ; для production задайте случайный `BETTER_AUTH_SECRET` длиной не менее 32 символов и `BETTER_AUTH_URL` с публичным HTTPS-адресом.

Для подключения к удалённой базе Turso укажите `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` в `.env.local`. В production переменная `TURSO_DATABASE_URL` обязательна. Не добавляйте реальные токены в репозиторий.

## База данных

- Клиент базы находится в `src/lib/db/client.ts` и предназначен только для серверного кода.
- SQL-миграции находятся в `src/lib/db/migrations` и применяются по порядку один раз.
- Локальная база хранится в `.local/`, эта папка исключена из Git.
- Better Auth хранит пользователей и сессии в Turso/libSQL; главная страница и API дневника требуют сессию.
- Записи питания, напитков, расходов, избранное и цели синхронизируются с аккаунтом. Фотографии пока хранятся локально в браузере.
- Фото и чеки лежат в IndexedDB конкретного браузера и устройства. Они не загружаются в Turso; экспорт включает только файлы, доступные в текущем браузере.
- Раздел «Данные и приватность» экспортирует JSON и позволяет удалить локальные данные. Удаление аккаунта требует подтверждения словом `DELETE` и удаляет профиль и связанные серверные записи.
- При кратком отсутствии сети новые записи, настройки, бюджет, избранное и удаления сохраняются локально и повторно отправляются после восстановления связи. Для финансово чувствительных или общих устройств используйте выход и очистку локальных данных.
- Миграции `0002_auth.sql`–`0004_preferences.sql` добавляют авторизацию, дневник и время напоминаний; применяйте их через `npm run db:migrate`.

## Production-развёртывание

1. Подготовьте HTTPS-хост, удалённую базу Turso и отдельные production значения `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `BETTER_AUTH_SECRET` (не менее 32 символов) и `BETTER_AUTH_URL`.
2. Примените SQL-миграции к выбранной базе командой `npm run db:migrate` из доверенного окружения.
3. Установите переменные окружения в менеджере секретов хостинга, затем соберите и запустите Next.js (`npm run build`, `npm run start`).
4. Проверьте регистрацию, вход/выход, закрытые API, экспорт и удаление аккаунта на отдельной тестовой учётной записи до включения для пользователей.

Фото не являются облачной резервной копией: потеря или очистка браузерного хранилища удалит локальные оригиналы. Не используйте общедоступные устройства для хранения личных записей.

### Vercel

- Импортируйте GitHub-репозиторий `xinz37759-collab/Water`. Vercel автоматически определит Next.js; используйте команды установки `npm install` и сборки `npm run build`, не задавая отдельную папку вывода.
- Добавьте в Vercel Environment Variables: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` и случайный `BETTER_AUTH_SECRET` не короче 32 символов. Укажите `BETTER_AUTH_URL` как точный HTTPS-origin production сайта, без завершающего `/` и без пути `/login`.
- Добавьте Turso-переменные и секрет для Preview-сборок тоже (лучше использовать отдельную Preview-базу). Preview-домен авторизации определяется автоматически по системным `VERCEL_ENV` и `VERCEL_URL`; для production используйте основной URL из `BETTER_AUTH_URL`.
- Перед первым входом примените миграции к выбранной Turso-базе: `npm run db:migrate` из окружения с её URL и токеном. Vercel автоматически миграции не запускает. После изменения переменных окружения создайте новый deployment.
- Не оставляйте `TURSO_DATABASE_URL` пустым: локальный SQLite fallback в production намеренно отключён, а файловая система Vercel не является постоянной базой данных.
